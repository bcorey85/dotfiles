# quickshell

QML desktop shell (`quickshell` from `extra`), **the bar and the notification daemon**. It replaced waybar and dunst outright, plus gsimplecal (calendar popup) and pavucontrol's daily use (per-app streams + output switching in the volume popup). blueman stays installed for pairing — the bar only connects already-paired devices.

Started by hypr autostart as `qs -p ~/.config/quickshell`; `shell.qml` loads one `Bar` per screen via `Variants`, the `Notifications` popup layer, and `Osd.qml`. The OSD only WATCHES state — pipewire for volume/mic, `/sys/class/backlight/*/brightness` for backlight — so the `XF86*` binds in `hyprland.lua` keep calling `wpctl`/`brightnessctl` and there is nothing to keep in sync. It suppresses its first second of events so it doesn't flash on login, and stays inert on a machine with no backlight. Modules live in `modules/`, shared chrome in `BarItem.qml`, dropdowns in `BarPopup.qml`.

Unlike every other desktop package it is NOT dark-only: `Theme.qml` watches the two theme state files with `FileView { watchChanges: true }` and repaints live. A running `qs` holds the palette table it was launched with, so a newly added family needs a restart, not just a toggle. Colors animate rather than snap: `Behavior on color` in `BarItem`/`Workspaces`, a single accent block that slides between workspace indices (`Item` wrapper around the `RowLayout` — anchors on a direct layout child are undefined behavior), a content fade in `BarPopup` driven off `contentItem` since the window itself pops in untransitioned, and a scale+fade on the launcher box driven from `open()` rather than bound to `visible`, which is already true by the time a binding would evaluate.

QML resolves types per directory: a file under `modules/` needs `import ".."` to see `Theme`, `BarItem` or `BarPopup`, and omitting it fails at runtime as `ReferenceError: Theme is not defined`, not at load. Workspace clicks must use Hyprland's lua dispatch form (`hl.dsp.focus({ workspace = N })`) — the legacy `workspace N` string is a syntax error. Dropdowns dismiss via `PopupWindow.grabFocus` (the compositor swallows the dismissing click, so `BarPopup.toggle()` ignores a click within 150ms of a hide — without that the opener reopens what it just closed); a hand-rolled `HyprlandFocusGrab` is NOT the way. A dropdown that hangs off the RIGHT edge of its bar item sets `rightAlignTo: root` and leaves `anchor.rect.x` alone — the popup owns its own width.

Notifications: `Notifs.qml` is the singleton that owns `org.freedesktop.Notifications` — nothing else may create a `NotificationServer`, the bus name is exclusive — and holds do-not-disturb plus the 50-entry history the bar's `NotifCenter` reads; a notification is dropped unless the `notification` signal handler sets `tracked = true`. Same handler dedups (same app + summary + body dismisses the older copy).

`Launcher.qml` replaced walker + elephant AND rofi's clipboard picker: apps from the `DesktopEntries` service, `=` for arithmetic, `>` to run a command, and cliphist history as a second mode. It is driven entirely over IPC from `hyprland.lua` — `qs ipc call launcher toggle` on `SUPER+Space`, `qs ipc call launcher clipboard` on `SUPER+CTRL+V`, `qs ipc call launcher power` on `SUPER+Escape` — via an `IpcHandler { target: "launcher" }`, whose functions need explicit return-type annotations (`function toggle(): void`) and which needs `import Quickshell.Io`. The power menu is a fourth MODE of the launcher rather than its own window. Its actions keep their declared order on an empty query — run through the ranker they would sort by name length. It is the ONLY surface here that takes keyboard focus: `WlrLayershell.keyboardFocus: Exclusive` while visible, `None` otherwise. Ranking is prefix > word-start > substring > scattered subsequence, with launch counts (`$XDG_STATE_HOME/quickshell-launcher.json`, machine-local) breaking ties. Websearch was deliberately not ported.

`Quickshell.env()` returns **null**, not `""`, when a variable is unset — test truthiness or paths come out as `"null/..."`. The bar's `Media` module reads MPRIS directly, but playerctl stays for the `XF86Audio` transport keys. Env knobs for running it beside another bar: `QS_BAR_EDGE=bottom` and `QS_BAR_EXCLUSIVE=0` (defaults are top + a reserved strip).

`Lock.qml` is the session lock, replacing hyprlock at both call sites (`SUPER+CTRL+L` and hypridle's `lock_cmd`, both now `qs ipc call lock lock`): `WlSessionLock` + `WlSessionLockSurface` for the surfaces and `PamContext` for auth, which asks for the password through a conversation message rather than up front — hold the typed value and `respond()` from `onPamMessage`, not at submit. It is a **singleton**, and singletons are created on first use, so `shell.qml` holds a `readonly property var sessionLock: Lock` purely to force it to load; without that reference its `IpcHandler` never registers and `qs ipc call lock lock` fails. The compositor holds the screen down, so a crash while locked leaves the session LOCKED — the way out is a TTY, and hyprlock stays installed for that reason. The surface renders `!lock.secure` as a visible warning.
