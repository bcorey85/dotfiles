# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Overview

Personal dotfiles managed with **GNU Stow** across WSL, Ubuntu, macOS, and Arch Linux. Each top-level directory is a stow package that mirrors the home directory structure (e.g., `nvim/.config/nvim/` symlinks to `~/.config/nvim/`).

## Setup & Install

```bash
./setup wsl    # or: ./setup ubuntu | ./setup mac | ./setup arch
```

Individual scripts in `install/` can be run standalone:

- `install/deps <platform>` - system packages (apt/brew/pacman)
- `install/fonts <platform>` - FiraCode Nerd Font
- `install/stow` - create all symlinks
- `install/wifi-be200` - Intel BE200 Wi-Fi 7 stability fix (writes `/etc/modprobe.d/iwlwifi.conf` to disable 802.11be; auto-skips if no BE200 detected)
- `install/zsh-plugins` - clone fzf-tab, zsh-autosuggestions, zsh-syntax-highlighting to `~/.zsh/plugins/`
- `install/mise` - global node LTS via mise (mise itself comes from `install/deps`; replaces `install/nvm` in `./setup` — `.zshrc` falls back to nvm on machines without mise)
- `install/hunk` - hunk diff viewer (`npm i -g hunkdiff` through mise's node, then `mise reshim`; skips if mise or mise-managed node is missing). npm-global because hunk ships on npm only — no apt/brew/pacman package
- `install/gh-dash` - gh-dash PR/issue dashboard extension (skips if gh missing or unauthenticated; re-run after `gh auth login`)
- `install/herdr` - herdr (agent-aware terminal multiplexer; **the multiplexer** — the previous multiplexer package was removed 2026-08 once the migration finished): checksum-verified GitHub release binary to `~/.local/bin` (no apt/pacman/brew package; upstream ships no checksum asset, so the script pins VERSION + SHA256 — bump both to upgrade, `--update` forces reinstall). Config is the stowed `herdr` package. Workflow plugins listed in the script's `PLUGINS` var are installed idempotently on every run, including the already-installed early-exit path — currently `lmilojevicc/herdr-splits.nvim` for C/M-hjkl nav (nvim side is `lua/plugins/herdr-splits.lua`, gated on `HERDR_ENV`, installed by lazy)
- `install/daily-recap` - schedule nightly `claude -p "/daily-recap"` (weekdays 18:00): compiles org captures (`~/vault/org`: journal entries + todo completions/opens) + GitHub activity into a structured daily note in the vault. macOS LaunchAgent / Linux systemd user timer; skips if claude absent. Capture side is `scripts/.local/bin/todo` + nvim-orgmode (herdr `prefix n`)
- `install/weekly-recap` - schedule `claude -p "/weekly-recap"` (Fridays 18:30, after Friday's daily compile): rolls the week's Daily notes into `~/vault/Weekly/<ISO-week>.md` (decisions, themes, shipped, current open org todos) and copies that week's `~/vault/org/achievements.org` entries verbatim into `~/vault/Achievements/<year>.md`. **Achievements are never inferred** — `scripts/.local/bin/achievement` (herdr `prefix n A`) is the only source, because nothing else in the pipeline records _who_ did the work. Same LaunchAgent/systemd pattern as daily-recap
- `install/starship` - Starship prompt
- `install/claude-plugins` - Claude Code plugins (skips if Claude not installed)
- `install/zsh` - set zsh as default shell

To add/remove a stow package, edit the `stow -R` line in `install/stow`.

## Stow Packages

- `nvim` → `~/.config/nvim/` — lazy.nvim config (bootstrap in `lua/config/lazy.lua`), one spec file per plugin in `lua/plugins/` (mini.* modules consolidated in `mini.lua`)
- `zsh` → `~/.zshrc` — Plugins, aliases, mise/pyenv/starship init (nvm fallback when mise absent)
- `claude` → `~/.claude/` — Agents, commands, settings, hooks
- `opencode` → `~/.config/opencode/` — Global config (`opencode.jsonc`), `AGENTS.md` global rules, `agents/` ported from claude. Auto-loads `~/.claude/skills/`
- `omp` → `~/.omp/agent/hooks/` — Oh My Pi harness. `claude-security-bridge.ts` delegates tool-call gating to the claude package's hook scripts (single source of truth — do NOT re-port the gates). omp ignores `~/.pi` and `~/.claude/agents`
- `aerospace` → `~/.config/aerospace/` — macOS tiling WM. Workspaces 1-9 pinned to external monitor, built-in screen dedicated to Teams (mac only)
- `starship` → `~/.config/starship.toml.template` — github prompt template; theme-mode generates the real `~/.config/starship.toml` (machine-local) with the active dark/light palette — see Theme below
- `scripts` → `~/.local/bin/` — herdr-sessionizer, dev utilities
- `git` → `~/.gitconfig` — Delta pager, side-by-side diffs. Per-machine identity in `~/.gitconfig.local`
- `quickshell` → `~/.config/quickshell/` — QML desktop shell (`quickshell` from `extra`), **the bar and the notification daemon**. It replaced waybar and dunst outright (both stow packages deleted 2026-08), plus gsimplecal (calendar popup) and pavucontrol's daily use (per-app streams + output switching in the volume popup). blueman stays installed for pairing — the bar only connects already-paired devices. Started by hypr autostart as `qs -p ~/.config/quickshell`; `shell.qml` loads one `Bar` per screen via `Variants`, the `Notifications` popup layer, and `Osd.qml`. The OSD is the media-key feedback nothing previously provided (swayosd was never installed): it only WATCHES state — pipewire for volume/mic, `/sys/class/backlight/*/brightness` for backlight — so the `XF86*` binds in `hyprland.lua` keep calling `wpctl`/`brightnessctl` and there is nothing to keep in sync. It suppresses its first second of events so it doesn't flash on login, and stays inert on a machine with no backlight. Modules live in `modules/`, shared chrome in `BarItem.qml`, dropdowns in `BarPopup.qml`. Unlike every other desktop package it is NOT dark-only: `Theme.qml` is a singleton that watches `~/.cache/theme-family` and `~/.cache/theme-mode` with `FileView { watchChanges: true }` and repaints live, so the bar follows `theme-mode` the way nvim/ghostty/herdr/starship do — all six families, both modes, with an unknown family falling back to vitesse rather than going unpainted. `theme-mode` writes NOTHING for quickshell, which is why a new family added there is silently ignored here until its palette lands in `Theme.qml`. A running `qs` holds the palette table it was launched with, so adding a family means restarting it, not just toggling. Colors animate rather than snap: `Behavior on color` in `BarItem`/`Workspaces`, a single accent block that slides between workspace indices (`Item` wrapper around the `RowLayout` — anchors on a direct layout child are undefined behavior), a content fade in `BarPopup` driven off `contentItem` since the window itself pops in untransitioned, and a scale+fade on the launcher box driven from `open()` rather than bound to `visible`, which is already true by the time a binding would evaluate. QML resolves types per directory: a file under `modules/` needs `import ".."` to see `Theme`, `BarItem` or `BarPopup`, and omitting it fails at runtime as `ReferenceError: Theme is not defined`, not at load. Workspace clicks must use Hyprland's lua dispatch form (`hl.dsp.focus({ workspace = N })`) — the daemon evaluates the dispatch argument as lua, so the legacy `workspace N` string is a syntax error. Dropdowns dismiss via `PopupWindow.grabFocus` (the compositor swallows the dismissing click, so `BarPopup.toggle()` ignores a click within 150ms of a hide — without that the opener reopens what it just closed); a hand-rolled `HyprlandFocusGrab` is NOT the way. A dropdown that hangs off the RIGHT edge of its bar item sets `rightAlignTo: root` and leaves `anchor.rect.x` alone — the popup owns its own width, and a module computing the offset by hand drifts silently the moment `implicitWidth` changes. Notifications: `Notifs.qml` is the singleton that owns `org.freedesktop.Notifications` — nothing else may create a `NotificationServer`, the bus name is exclusive — and holds do-not-disturb plus the 50-entry history the bar's `NotifCenter` reads; a notification is dropped unless the `notification` signal handler sets `tracked = true`. Same handler dedups (same app + summary + body dismisses the older copy), which dunst did for free. `Launcher.qml` replaced walker + elephant (7 AUR packages, 2 autostart daemons) AND rofi's clipboard picker: apps from the `DesktopEntries` service, `=` for arithmetic, `>` to run a command, and cliphist history as a second mode. It is driven entirely over IPC from `hyprland.lua` — `qs ipc call launcher toggle` on `SUPER+Space`, `qs ipc call launcher clipboard` on `SUPER+CTRL+V`, `qs ipc call launcher power` on `SUPER+Escape` — via an `IpcHandler { target: "launcher" }`, whose functions need explicit return-type annotations (`function toggle(): void`) and which needs `import Quickshell.Io`. The power menu is a fourth MODE of the launcher rather than its own window (it reuses the overlay, keyboard focus, ranking and IPC already there); it deleted `scripts/.local/bin/hypr-power-menu`, which was the last thing still shelling out to rofi. Its actions keep their declared order on an empty query — run through the ranker they would sort by name length. It is the ONLY surface here that takes keyboard focus: `WlrLayershell.keyboardFocus: Exclusive` while visible, `None` otherwise, so it never holds the keyboard when closed. Ranking is prefix > word-start > substring > scattered subsequence, with launch counts (`$XDG_STATE_HOME/quickshell-launcher.json`, machine-local) breaking ties. Websearch was deliberately not ported. `Quickshell.env()` returns **null**, not `""`, when a variable is unset — test truthiness or paths come out as `"null/..."`. The bar's `Media` module reads MPRIS directly, but playerctl stays for the `XF86Audio` transport keys. Env knobs for running it beside another bar: `QS_BAR_EDGE=bottom` and `QS_BAR_EXCLUSIVE=0` (defaults are top + a reserved strip, waybar's old geometry). `Lock.qml` is the session lock, replacing hyprlock at both call sites (`SUPER+CTRL+L` and hypridle's `lock_cmd`, both now `qs ipc call lock lock`): `WlSessionLock` + `WlSessionLockSurface` for the surfaces and `PamContext` for auth, which asks for the password through a conversation message rather than up front — hold the typed value and `respond()` from `onPamMessage`, not at submit. It is a **singleton**, and singletons are created on first use, so `shell.qml` holds a `readonly property var sessionLock: Lock` purely to force it to load; without that reference its `IpcHandler` never registers and `qs ipc call lock lock` fails. The compositor, not this process, holds the screen down, so a crash while locked leaves the session LOCKED rather than exposed — the way out is a TTY, and hyprlock stays installed for that reason. The surface renders `!lock.secure` as a visible warning so a lock the compositor never confirmed doesn't look identical to a working one
- `herdr` → `~/.config/herdr/` — `config.toml.template` — prefix C-Space, popup fleet, harpoon on `alt+1..4` via `herdr-harpoon`). Session persistence + agent resume are built in (no resurrect/continuum analogue needed). Stowed file is the TEMPLATE: `theme-mode` regenerates the real machine-local `config.toml` from it and runs `herdr server reload-config` — edit the template, never the generated file
- `hunk` → `~/.config/hunk/` — `extensions/claude-review.ts` — single-file hunk extension (id `claude-review`; hunk loads every file directly under `extensions/`). GitHub-style viewed marks: `v` toggle viewed, `V` drop viewed files from the review entirely, `S` `git add` the viewed set, `X` clear. `L` hands the popup off to lazygit (see `hunk-review-popup` below). Marks are **file-level** — `transformChangeset` may filter `files`, but a file's hunks live in opaque `metadata` the renderer owns, so a single hunk cannot be dropped. `v` collapses the file in place through a registered file view (`registerFileView` + `ctx.fileViews.select`) — lands on the keypress, and is the only viewed indicator hunk's UI can show — then jumps to the next unviewed file via `ctx.navigation.selectFile`, wrapping once. Collapse does NOT survive a load: hunk never auto-selects a matching view, and `ExtensionEventContext` carries no `fileViews`, so a previously-marked file opens raw. Conversely, hunk reuses a prepared layout until the file, width, or registration changes, so clearing marks under an already-collapsed file needs `ctx.fileViews.refresh(VIEW_ID)` — `select(null)` reaches only the selected file (`X` and `S` both refresh). `V` and `S` change what the changeset contains, which `transformChangeset` and the git index only reflect at load, so both drive a live reload by shelling out to `hunk session reload <id> -- diff` (async and detached — the RPC comes back into this same process, so blocking on it deadlocks the UI; the session is found by pid, falling back to the sole session matching the repo root). Reload only applies to plain working-tree reviews: `--staged`/ref diffs would have their spec silently swapped, and the lazygit pager path (`inputKind: "patch"`) has no source to re-read at all — both fall back to a toast. Theming is `~/.config/hunk/config.toml`, set by `theme-mode`'s `hunk_apply()`: `theme =` maps to a **builtin** per family x mode via `hunk_theme()` (each family → `vitesse-{dark,light}`), plus `transparent_background = true` so hunk's chrome inherits the terminal background instead of painting the builtin's own — without it dark mode reads as a gray box inside ghostty/herdr's black. (`theme = "custom"` + a `[custom_theme]` table of 33 hex keys is also supported if a builtin ever stops being close enough.) That file is **not** stowed and has no template, unlike herdr/starship: hunk writes it itself (the View menu persists theme, wrap, line numbers), so `theme-mode` sets only the keys it owns via `hunk_set()` — anchored to top-level keys and inserted above the first table header, since a key appended below one would silently join that table. No live repaint — hunk reads config at launch. State is machine-local under `$XDG_STATE_HOME/hunk-claude/<repo-slug>.json`, keyed by a hash of each file's patch so editing a marked file un-marks it. Marks outlive a changeset (a marked file can be staged or deleted elsewhere), and `git add` is atomic over its pathspec — one dead path fails the whole stage — so `S` intersects the marks with the paths `transformChangeset` saw and skips the rest instead of pruning them, since a path-filtered review is legitimately narrower than the mark set. Built-in inline notes (`c`) are mirrored to `<repo-slug>.comments.jsonl`, read by `claude/.claude/skills/cc/hunk-comments-consume` (`list`/`resolve`, one of `/cc`'s two readers alongside nvim). The slug is `<basename>-<sha256(repoRoot)[0:12]>` and is duplicated in the extension and that script — change one, change both. Because we own the JSONL, resolve is a **true** delete. hunk is a Node app installed by `install/hunk` (npm-global through mise). Because mise puts its shims on PATH via a `.zshrc` hook, `hunk` is NOT resolvable from the herdr server's login environment — the `prefix d` binding prepends `${MISE_DATA_DIR:-${XDG_DATA_HOME:-$HOME/.local/share}/mise}/shims` itself; herdr popups hold on error instead of flash-closing. Inside that it runs `scripts/.local/bin/hunk-review-popup`, which runs `hunk diff` and then execs whatever tool the extension's `L` wrote into `$HUNK_REVIEW_HANDOFF` (currently only `lazygit`) — herdr popups are session-modal, so `prefix g` cannot reach herdr from inside the review and a second popup cannot open over the first; keeping both tools in the one popup shell is the only way review → git costs a single key. `L` quits by `process.kill(process.pid, "SIGTERM")`: hunk's TUI installs SIGINT/SIGTERM on the same shutdown path as `q`, so the terminal is restored before the wrapper execs. Its extension API is `apiVersion 2` and documented-experimental, so re-read `dist/npm/extension/extension-api/types.d.ts` in the installed package before changing the extension

## CRITICAL: Cross-Platform Compatibility

**Everything in this repo MUST work on all four platforms: WSL, Ubuntu, macOS, and Arch Linux.** Before installing any tool, adding any dependency, or making any change:

1. **Only use `apt` (WSL/Ubuntu), `brew` (macOS), and `pacman` (Arch)** for package installs — never `cargo`, `pip install --global`, `snap`, or other package managers
2. **Add new dependencies to `install/deps`** in ALL platform cases (`wsl|ubuntu`, `mac`, and `arch`)
3. **Never hardcode platform-specific paths** — use `$HOME`, `~`, or detect the platform
4. **Per-machine config** (user identity, credentials, machine-specific paths) belongs in local files (e.g., `~/.gitconfig.local`), NOT in stow-managed files

Second family — **flexoki** (kepano/flexoki-neovim; dark "moon" `#100f0f` / light "dawn" `#fffcf0`; one colorscheme "flexoki" follows `background`, so `colors_name` is pinned like vitesse's; stock comments fail 4.5:1 both modes (dark base-700 `#575653` ~2.5, light base-300 `#b7b5ac` ~1.9) so the fixup lifts to base-500 `#878580` / base-600 `#6f6e69`, flat — flexoki comments are not italic; ghostty uses the BUILTINS "Flexoki Dark"/"Flexoki Light", so no file under `ghostty/themes/`; **flexoki is NOT a hunk builtin** — it ships a full `[custom_theme]` + `[custom_theme.syntax_scopes]` block resolved from the colorscheme's own groups (Keyword magenta, String green, Number/Boolean/Character/Special orange, Function blue, Type/Include cyan, Constant yellow, Macro/`@string.escape` purple, Identifier/Operator tx, punctuation/parameters tx2) over a base picked for its NEUTRALS — kanagawa-dragon / gruvbox-light-medium, whose fg and warm cast nearly match flexoki's, because the base still owns any unnamed scope and `syntaxColors.default`). Third family — **bamboo** (ribru17/bamboo.nvim; dark "vulgaris" `#252623` / light `#fafae0`, both warm; one colorscheme "bamboo" picks its style from `background` and always sets `colors_name` "bamboo", so both are pinned; the `Comment` group (light_grey `#838781`) misses 4.5:1 in both modes (~4.2 dark, ~3.5 light) so the fixup lifts to `#8e938c` / `#66695f`, italic — treesitter's `@comment` is a separate, already-legible bg_yellow and is left alone; headings come from the theme's own rainbow blends (H1 `blend(red, inverse, .25)`, H2 the orange); **bamboo is neither a ghostty nor a hunk builtin** — ghostty gets custom `ghostty/themes/bamboo-{dark,light}` files whose ANSI is the theme's own `terminal.lua` mapping, and hunk gets a full `[custom_theme]` + `syntax_scopes` block resolved from the colorscheme's live groups (Keyword/Statement/PreProc/Include/`@tag` purple, String green, Constant + its Number/Boolean/Character/Float links orange, Function blue, Type yellow, Macro bright-purple, `@string.escape` + `@variable.parameter` coral, `@variable.member`/`@attribute` cyan, `@variable.builtin` red, `@module` light-blue, `@function.builtin` orange, Delimiter light-grey, Operator the theme's `blend(purple, fg, .375)`, comment the bg_yellow `@comment`) over gruvbox-dark-medium / gruvbox-light-medium, picked because their neutrals nearly match; light's prompt palette darkens the slots that miss 4.5:1 on cream (orange, yellow, cyan, green)). Roles the generic hunk block used to collapse into `text`/`punct`/`num`/`typ`/`esc` now have their own vars (`cmt mem param attr tag vbi imp pre prim ns mac bfn`), each DEFAULTED to its old value so every other family's block is byte-identical. Fourth/fifth/sixth families — **gruvbox** (ellisonleao/gruvbox.nvim — ORIGINAL gruvbox, medium contrast, NOT sainnhe/gruvbox-material's softer palette (red `#fb4934` vs material's `#f2594b`, fg `#ebdbb2` vs `#e2cca9`); dark `#282828` / light cream `#fbf1c7`, one colorscheme `gruvbox` follows `background` so `colors_name` is pinned; its ONE comment grey `#928374` misses 4.5:1 at both ends and has to move in opposite directions — lifted to `#9e8d7d` dark (~4.6:1), darkened to `#776a5e` light (~4.6:1), italic), **melange** (savq/melange-nvim; warm brown-black `#292522` / neutral `#f1f1f1` — the only non-cream light ground in the set; one colorscheme follows `background`, `colors_name` pinned; **the only family with NO comment fixup** — stock `#c1a78e` ~6.7:1 and `#7d6658` ~4.8:1 both clear unmodified, and `theme-sync` treats `fixup` as optional), and **kanagawa** (rebelot/kanagawa.nvim, dragon `#181616` / lotus `#f2ecbc`; **the only family shipping one colorscheme PER variant** — `kanagawa-dragon`/`kanagawa-lotus` rather than switching on `background` — so `schemes` differ by mode while both register `colors_name` "kanagawa"; comments lifted to `#838a82` / `#6a6a5e`, italic, the same values the hunk and herdr blocks already carried). Seventh family — **gruvbox-material** (sainnhe/gruvbox-material, `background = "hard"`, `foreground = "original"` set from `theme-sync`'s `pre()` hook — the only family using it; run side by side with `gruvbox` for A/B. `original` foreground means its ACCENTS are byte-identical to original gruvbox's (`#fb4934`/`#ebdbb2`), while `hard` puts them on grounds a stop past gruvbox's medium — `#1d2021` dark / `#f9f5d7` light — so ghostty maps to the "Gruvbox Dark/Light **Hard**" builtins; ghostty's own "Gruvbox Material Dark/Light" builtins are medium ground AND the MATERIAL foreground (`#d4be98`, red `#ea6962`), matching on neither axis. What else differs is CHROME (bg1 `#282828` / `#f5edca`, tighter and warmer than gruvbox's bg1..bg3) and ROLE assignment (Function green, Operator/StorageClass/Tag orange, Constant/Macro aqua, PreProc/Include/`@attribute` purple, `@module` yellow, Identifier/`@variable.member` blue) — both of which the hunk `[custom_theme]` and herdr blocks encode; diff washes are the theme's own `bg_diff_green`/`bg_diff_red`. Same comment grey `#928374`, still short at both hard ends (4.47:1 on `#1d2021`, ~3.3:1 on `#f9f5d7`), so the same two-way fixup `#9e8d7d`/`#776a5e`, italic; hunk base stays `gruvbox-{dark,light}-medium` — the nearest neutrals, since hunk ships no hard variant.) The system collapsed from nine families to vitesse-only, then flexoki, bamboo, gruvbox, gruvbox-material, melange and kanagawa were re-added on top; the `theme-mode` script (scripts package) keeps the two-axis machinery — **family** (`~/.cache/theme-family`; `theme-mode list`; `theme-mode use <family> [mode]`) × **mode** (`~/.cache/theme-mode` dark/light, toggled by `theme-mode` / nvim `<leader>ut`); the remaining per-family branches in `hunk_custom_theme()`/`herdr_palette()` (flume, zenbones, tempus) are retained inert as the pattern for re-adding another. Consumers: nvim polls both state files (lua/config/theme-sync.lua — its FAMILIES table maps schemes and owns all theme-reactive overrides: markdown headings, prose calm, gitsigns word-diff, the comment-contrast fixup); ghostty gets `theme-switch.conf` (machine-local include written by the script; reload ctrl+shift+, — vitesse and bamboo ship custom files under `ghostty/themes/`); herdr is mode-only, on the same template contract as starship: theme-mode substitutes the `__THEME_MODE_PALETTE__` marker in the stowed `config.toml.template` with `herdr_palette()`'s `[theme.custom]` block, writes the real machine-local `~/.config/herdr/config.toml`, and runs `herdr server reload-config` so attached clients repaint live — herdr's own `auto_switch` stays off because it keys off the terminal's reported appearance, not the state files; starship does a family x mode swap (theme-mode regenerates the REAL `~/.config/starship.toml` — starship's default path — from the stowed `~/.config/starship.toml.template` with the active `<family>-<mode>` palette; starship has no include but re-reads that path each prompt, so every open shell flips live with no reload and no STARSHIP_CONFIG. `.zshrc` bootstraps the file from the template on a fresh machine). Adding a family = six touchpoints, listed in the `theme-mode` header — don't duplicate the checklist here; the sixth is quickshell's `Theme.qml` palette table, which `theme-mode` writes nothing for (that singleton watches the state files itself) and which falls back to vitesse for a family it doesn't know, so a miss is silent. **Dark-only, no mode/family axis**: hyprland — repainted to vitesse-dark hex values, hardcoded rather than read from the state files or a template. GTK/Qt apps use Adwaita-dark. The launcher used to be here (walker, dark-only GTK4 CSS) and so was the lock screen (hyprlock) and the power menu (rofi); `Launcher.qml` and `Lock.qml` moved all three onto the theme axis, which was the point. `hyprlock.conf` and the hyprlock package stay as the manual fallback for a machine where quickshell isn't running — nothing routes to them any more (`SUPER+CTRL+L` and hypridle's `lock_cmd` both call `qs ipc call lock lock`), so hyprlock keeps its dark-only hardcoded hex and is off the theme axis by design.
- **Font**: FiraCode Nerd Font Mono, Retina, 13pt (ghostty; machine-local `~/.config/ghostty/local.conf` overrides the size — last include wins)
- **Platform guards**: Use `command -v <tool> &>/dev/null &&` before tool-specific init (see .zshrc)
- **Install scripts**: All use the same color output pattern (`print_success`, `print_error`, `print_info`) with `set -e`
- **Stow structure**: `<package>/<home-relative-path>` (e.g., `nvim/.config/nvim/init.lua` becomes `~/.config/nvim/init.lua`)

## Working with This Repo

- **Direct-edit repo**: the global delegation mandate does not apply here — edit files directly instead of dispatching coder subagents
- **No rationale in agent/skill bodies.** Every line under `claude/.claude/agents/` and `claude/.claude/skills/` is paid for on every dispatch. Write the RULE, not why it exists: no measurement results, no dispatch/finding counts, no dates, no "this was retired because", no "measured basis", no account of the incident that motivated it. Also banned: persuasion (arguing a rule's merits to its reader), restating what a capable model does unprompted, and a second phrasing of a rule already stated in the same file. If a line doesn't change what the agent does, it doesn't ship. If a rule needs defending, the defense goes in the git commit message or `~/agent-evals/`, never in the file. Existing rationale paragraphs are debt — delete them when you touch the surrounding text.
- **Toolkit-edit propagation sweep** (run before claiming done on any change to an agent/skill under `claude/.claude/`; a done-claim without it is a guess): (1) `grep -r` the changed tag/field/section name across the repo — update every consumer (routing in `review-loop.md`, the telemetry log call, `audit/review.md`); (2) patch the ported copy in `opencode/.config/opencode/agents/` or state that you're knowingly skipping it (adaptations preserved there: CLAUDE.md→AGENTS.md, no Persistent Memory, opencode frontmatter); (3) check inheriting variants (`-deep` agents inherit by reference — usually no edit; coders preload `coder-core`, which opencode auto-loads).
- Configs are live-symlinked; edits in `~/dotfiles/` take effect immediately (herdr and starship are the exceptions — their stowed files are TEMPLATES, regenerated by `theme-mode`)
- Neovim plugins are managed by **lazy.nvim** (bootstrap in `lua/config/lazy.lua`); specs live in `lua/plugins/` (one file per plugin; all `mini.*` modules share a single consolidated `mini.lua` spec because lazy merges same-repo specs and only keeps one `config`). Revisions are pinned in `lazy-lock.json`; use `:Lazy` (status/install/update/clean) — `:PackUpdate`/`:PackStatus`/`:PackClean` remain as compat aliases. Load triggers (`event`/`ft`/`cmd`/`keys`) are set per spec; a spec with no trigger and no `lazy = true` loads eagerly at startup. LSP is wired from the `lspconfig` spec's `config` (gated on `BufReadPre`) so `config.lsp` runs only after nvim-lspconfig is on the rtp.
- Zsh plugins are git-cloned to `~/.zsh/plugins/` (not in this repo, installed by `install/zsh-plugins`)
- opencode global config is stowed at `opencode/.config/opencode/opencode.jsonc`; it auto-loads external skills from `~/.claude/skills/`, so existing stowed claude skills work as-is. opencode-specific agents/commands live under `~/.config/opencode/agent(s)/` and `command(s)/` (port from claude separately if desired)
- omp (Oh My Pi) reads `~/.omp/agent/`, NOT `~/.pi` (the legacy pi package's extensions are inert under omp) and NOT `~/.claude/agents` or `~/.claude/settings.json` hooks. Its hook discovery loads `hooks/pre|post/*.ts` factories. The security gates are NOT ported — `omp/.omp/agent/hooks/pre/claude-security-bridge.ts` shells out to the real scripts in `~/.claude/scripts/`, so changes to those scripts' stdin/stdout contract (hook JSON in, `permissionDecision` JSON or exit-2 out) must keep the bridge compatible. Regenerating the CB hooks needs no bridge change as long as the contract holds. omp hooks load at session start — restart omp after stowing
