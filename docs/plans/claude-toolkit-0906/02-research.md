# Research: Claude Code toolkit hook/gate/agent/skill architecture

## Findings

### 1. Hook events registered in `claude/.claude/settings.json`

File: `claude/.claude/settings.json:1-`. The `hooks` object registers five event types:

- **`Notification`** — three matchers, each firing `~/.claude/scripts/notify`:
  - `idle_prompt` → `notify 'Claude Code' 'Ready for input'`
  - `permission_prompt` → `notify 'Claude Code' 'Permission needed'`
  - `task_complete` → `notify 'Claude Code' 'Task complete'`
- **`PostToolUse`** — six matcher blocks:
  - `Write|Edit` → `calibration-refs-guard.sh`
  - `Skill` → `log-skill-use.sh`
  - `Agent` → `review-commit-gate.sh` then `log-agent-usage.sh` (two hooks, same matcher block)
  - `Write|Edit` (separate block) → `prettier-hook.sh`
  - `Write|Edit` (separate block) → `eslint-hook.sh`
  - `Write|Edit` (separate block) → `claudemd-linecount.sh`, `dead-prose-gate.sh`, `comment-bloat-gate.sh` (three hooks in one block)
- **`PreToolUse`** — six matcher blocks:
  - `Bash` → `bash-safety-gate.sh`, `git-discipline-gate.sh`, `review-commit-gate.sh` (in that order)
  - `Read|Grep` → `block-credential-read.sh`
  - `Read` (separate block) → `test-blindness-gate.sh`
  - `(Write|Edit|MultiEdit|NotebookEdit)` → `write-edit-safety-gate.sh`, `spec-budget-gate.sh`, `test-ownership-gate.sh`, `test-edit-telemetry.sh`
  - `Agent` → `agent-model-guard.sh`
  - `AskUserQuestion` → `notify 'Claude Code' 'Question for you'`
- **`SessionStart`** — two blocks: matcher `""` → `warn-skip-hooks.sh`, `calibration-guard.sh`; matcher `"*"` → `bash ~/.claude/hooks/herdr-agent-state.sh session` (timeout 10; note this points at `~/.claude/hooks/`, a directory distinct from `~/.claude/scripts/`).
- **`UserPromptSubmit`** — no matcher (fires on every prompt) → `log-skill-use.sh`.

Also relevant top-level config in the same file: `permissions.allow`/`deny` (an allowlist of read-only/inspection commands plus an explicit `deny` list — `sudo *`, `rm -rf /`, `chmod 777 *`, `gh pr create:*`, `gh pr merge:*`), `permissions.defaultMode: "auto"`, `model: "opus"` (main-session default), `skillOverrides` (marks several skills `user-invocable-only`), `worktree.baseRef: "fresh"`, `statusLine` command, and `enabledPlugins` (context7, lua-lsp, pyright-lsp, security-guidance, skill-creator, typescript-lsp, plus three third-party marketplace plugins: ponytail, caveman, simple-english).

### 2 & 3. Scripts under `claude/.claude/scripts/` — behavior, I/O, and the stdin/stdout contract

All hook scripts read the full hook-event JSON from stdin (`INPUT=$(cat)` or `input=$(cat)`) and parse fields with `jq` (with a `python3` fallback in the four "CB Security Hooks" scripts). The contract — stated explicitly in several scripts' headers (e.g. `test-blindness-gate.sh:28-29`, `test-ownership-gate.sh:27-28`) and in the global `claude/.claude/CLAUDE.md` under "Safety Rails" — is:

> hook JSON on stdin; empty stdout = allow; a JSON object `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}` on stdout = deny; `CLAUDE_SKIP_HOOKS` env var set to any non-empty value = universal bypass (checked first in nearly every script, e.g. `bash-safety-gate.sh:15`, `agent-model-guard.sh:30`, `test-blindness-gate.sh:31`).

Two different deny mechanisms exist side by side:

- The four **"CB Security Hooks" generated scripts** (`bash-safety-gate.sh`, `write-edit-safety-gate.sh`, `block-credential-read.sh`, and the pattern is also used by `agent-model-guard.sh`) deny by printing the `permissionDecision":"deny"` JSON to **stdout** and exiting **0**. Each carries the header `# GENERATED — do not edit directly` and a version comment (`Version: 0.1.6`), and each installs an `ERR` trap that fails closed (denies) if the script itself throws.
- The **hand-written discipline/ownership gates** (`git-discipline-gate.sh`, `review-commit-gate.sh`) deny by writing a message to **stderr** and exiting **2** (the harness's other convention for PreToolUse block, "stderr fed back to the model" per `git-discipline-gate.sh:13`).
- `test-blindness-gate.sh` and `test-ownership-gate.sh` use the stdout-JSON convention (not exit 2) despite being hand-written; both explicitly document the same "hook JSON in / empty=allow / permissionDecision JSON=deny / CLAUDE_SKIP_HOOKS escape" contract in their header comments.
- `spec-budget-gate.sh` and `comment-bloat-gate.sh` mix conventions: `spec-budget-gate.sh` denies via stdout JSON (`deny()` helper, `spec-budget-gate.sh:114-117`); `comment-bloat-gate.sh` denies via stderr + exit 2 (`comment-bloat-gate.sh:31-35,43-46`).
- Pure telemetry/log scripts (`log-agent-usage.sh`, `log-skill-use.sh`, `test-edit-telemetry.sh`) never emit a `permissionDecision` and always exit 0 — documented explicitly as "LOG-ONLY, never blocks" in `test-edit-telemetry.sh:1-13`.

### 4. Global rules content and expression style

`claude/.claude/CLAUDE.md` (the stowed source for `~/.claude/CLAUDE.md`, shown in full via system context) contains sections: Precedence, Communication (laconic-mode prose directive — pure prose, unenforced by any script), **Safety Rails** (prose that _names_ the five hook scripts as enforcing SSH/credential/sudo/force-push/main-commit/stash/amend/reset/pipe-to-shell rules — the prose is a human-readable index to already-mechanized rules, not itself the enforcement), Orchestration (prose-only delegation/routing rules for the main session — explicitly stated to not bind subagents; no script mechanizes delegation choice, model pairing beyond `agent-model-guard.sh`, or workflow routing), Tools (prose: "file changes go through Write/Edit", "prefer LSP over grep+Read" — not mechanically enforced; shell-write bypass of the Write/Edit hook pipeline is a known/named gap, not gated), Quality Checks & Failure Budget (prose 2-run cap — not mechanically enforced; `coder-core` SKILL.md restates it as a "HARD RULE" in prose only), Tool Use Efficiency (prose), Engineering Judgment (prose), Git (partially mechanized: commit-on-main/stash/amend/force-push ARE hook-enforced per Safety Rails; "keep diffs focused" and worktree-branch-rename conventions are prose-only), Security (prose: "Ansible Vault for secrets" — not mechanically checked), Obsidian (prose), Maintaining These Rules (prose meta-rule about rule lifecycle).

### 9. Telemetry/logging scripts — data format

All telemetry scripts write **JSONL** (one JSON object per line) via `jq -c`/`jq -cn`, always include a `date`/`ts` field (ISO 8601 UTC via `now | todate` or `date -u +%Y-%m-%dT%H:%M:%SZ`), and the three "structured CLI" loggers (`log-escape`, `log-spec-run`, `review/log-review-finding`) share one input convention: `key=value` positional CLI args, validated (reject unquoted spaces in non-free-text fields, reject unknown enum values for `class=`/`guard=`/`result=`/`verdict=`/`kind=`), with a `schema_version` field that is bumped only on breaking vocabulary/meaning changes (never for additive fields) so downstream `/audit` tooling can filter to "current version". The two hook-driven loggers (`log-agent-usage.sh`, `log-skill-use.sh`) instead read structured JSON directly off the PostToolUse/UserPromptSubmit hook payload via `jq` filters and never take CLI args. Output paths are all overridable via env var (`$AGENT_USAGE_FILE`, `$SKILL_USAGE_FILE`, `$REVIEW_ESCAPES_FILE`, `$SPEC_RUNS_FILE`, `$REVIEW_FINDINGS_FILE`), defaulting to flat files directly under `~/.claude/` (`agent-usage.jsonl`, `skill-usage.jsonl`, `review-escapes.jsonl`, `spec-runs.jsonl`, `review-findings.jsonl`) — i.e. these logs are **global across all repos**, disambiguated only by a `repo` field inside each row (computed via the shared `repo-name` script in three of the five, to normalize worktree checkout names back to the canonical repo).

### 11. `review/log-review-finding` and `_shared/finding-log.md` — structure of persisted output

`_shared/finding-log.md` (68 lines) is the **canonical instruction doc**, pointed to by every gate that emits findings instead of being restated per-gate. It documents the two-row-kind schema (`kind=run` — one per gate dispatch including silent ones, so "PASS rate" has a denominator; `kind=finding` — one per actual finding) and gives the exact invocation shape:

```
bash "$L" kind=run "${C[@]}" gate=<agent> n_findings=<n> diff_loc=<n> result=<PASS|PASS WITH WARNINGS|NEEDS CHANGES|NOT DISPATCHED>
bash "$L" kind=finding "${C[@]}" gate=<agent> disposition=<fix|ask|nit> [blocker=yes] class=<...> file=<path> line=<n> actioned=<fixed|skipped_fp|deferred|ask|none> desc="<one line>"
```

where `C=(...)` is a **shared context array** (`repo=`, `branch=`, `lane=`, `scope=`, `phase=`, `iter=`) expanded with `"${C[@]}"` — the file explicitly warns that quoting it as a single string instead of an array "collapses all of them into repo=, which destroys every join key". Structured fields: `kind`, `gate` (literal agent name, tiers never collapsed), `disposition`/`blocker`/`class`/`file`/`line`/`actioned`/`fix_induced` — all from closed vocabularies enforced by the script itself. Free-form prose is limited to exactly two fields: `desc="<one line>"` (finding rows) and `result=` free text is normalized by the script into one of 4 buckets rather than staying free-form.

`review/log-review-finding` (194 lines, executable bash) is the **implementation**: parses `kind=value` CLI args into a JSON object via `jq`, validates `kind` is `run`/`finding` (required), `gate` is non-empty (required), resolves canonical `repo` via `../../scripts/repo-name`, normalizes `result=` (run-kind only) through a fuzzy synonym map (`CLEAN*`/`INTENT ALIGNED`→`PASS`; `FINDINGS`/`GAPS`/`GAPS FOUND`/`RESIDUE`→`NEEDS CHANGES`; anything unmappable → hard refuse with `exit 1`), validates `class=` (finding-kind only) against the same closed vocabulary as `log-escape` ("so the caught and escaped sides cross-tabulate"), requires `n_findings=` on `run` rows (explicitly to prevent a "logged but counts as nothing" row), and finally appends the JSON line to `$REVIEW_FINDINGS_FILE` or `~/.claude/review-findings.jsonl`. `schema_version=2`. The file also documents (but does not itself validate) `fix_induced=yes|no|bug`, where `bug` "auto-promotes to blocker" — that promotion is a **caller-side prose rule** (stated in both `finding-log.md` and the script's own header comment) that the script does not enforce (no code path checks `fix_induced=bug` implies `blocker=yes` was also passed).

## Patterns Found

- **Two deny conventions coexist**: stdout-JSON-with-exit-0 (all four "CB Security Hooks generated" scripts, plus `agent-model-guard.sh`, `test-blindness-gate.sh`, `test-ownership-gate.sh`, `spec-budget-gate.sh`) versus stderr-message-with-exit-2 (`git-discipline-gate.sh`, `review-commit-gate.sh`, `comment-bloat-gate.sh`). Both are documented as valid in different places (global CLAUDE.md says "exit-2 out"; several script headers say "permissionDecision JSON... = deny").
- **`CLAUDE_SKIP_HOOKS` universal bypass** is checked first in nearly every gate script, and `warn-skip-hooks.sh` runs at SessionStart specifically to surface when it's set.
- **Fail-closed on internal error**: the four generated scripts install a bash `ERR` trap that emits a deny decision rather than letting the script's own bug silently allow (`bash-safety-gate.sh:14`).
- **Fast-path pre-filter**: the generated scripts run one large combined regex to early-`exit 0` before evaluating ~50 individual finer-grained checks (`bash-safety-gate.sh:61`, `write-edit-safety-gate.sh:177`, `block-credential-read.sh:88`) — a performance pattern, not a correctness one.
- **Cross-event state machines**: `review-commit-gate.sh` is the only gate that correlates two different hook events (`PostToolUse`/Agent to arm, `PreToolUse`/Bash to block+clear) via a session-scoped file under `~/.claude/state/review-gate/`, with explicit self-pruning (`-mtime +2 -delete`).
- **Agent-scoped gates via `agent_type`**: `test-blindness-gate.sh`/`test-ownership-gate.sh`/`test-edit-telemetry.sh` all read a top-level `agent_type` field (distinct from `.tool_input.subagent_type`, which is what `agent-model-guard.sh` and `review-commit-gate.sh` read) — two different identity fields are in play depending on which hook-input shape the script targets.
- **"Mechanize the rule, not just state it" migration pattern**: `git-discipline-gate.sh`, `review-commit-gate.sh`, `test-blindness-gate.sh`, and `test-ownership-gate.sh` all explicitly document (in header comments) a prior prose-only rule that measurably leaked, followed by conversion to a hook — a recurring repo-level pattern of graduating repeatedly-violated prose rules into scripts.
- **Deliberate non-closure of a known displacement vector**, paired with telemetry rather than a stronger gate, to measure whether closing one vector pushes the same failure elsewhere (`test-blindness-gate.sh:24-26`, `test-ownership-gate.sh` header).
- **Shared canonical vocabularies across independent scripts**: the `class=` enum (bug/smell/duplication/complexity/plan-drift/test-gap/weak-assertion/security/perf/correctness/docs/other) is duplicated verbatim in `log-escape` and `review/log-review-finding` specifically so the two logs "cross-tabulate" — a hand-maintained (not shared-file-sourced) vocabulary duplication.
- **Word-budget-by-displacement**: `spec-budget-gate.sh` is the only content-size gate; it recomputes prospective word counts from the pending diff rather than requiring a post-write check, and explicitly forbids the model from self-raising its own ceilings.
